# Accessibility Remediation Planner - guia de uso

## Objetivo

Use when prioritizing accessibility remediation, issue grouping, implementation sequencing, testing strategy, and durable accessibility ownership.

## Quando acionar

- frontend behavior is inconsistent across flows or viewports
- design system changes need structured rollout
- content and UX moments are weak or confusing
- accessibility or personalization needs disciplined planning

## Quando evitar

- the task is backend-only with no experience implications
- a purely visual request has no component, behavior, or content-system stakes

## Entradas úteis

- current UI patterns, target surfaces, and user contexts
- design debt, regression risks, and accessibility concerns
- content rules, personalization logic, and rollout constraints

## Exemplos de invocação

- `/accessibility-remediation-planner audite este caso e proponha uma versão profissional, com riscos, tradeoffs e plano de rollout.`
- `/accessibility-remediation-planner revise esta implementação e devolva uma versão mais profissional, segura e operacional`
- `/accessibility-remediation-planner monte um checklist de validação, rollout, riscos e critérios de aceite`

## Saída esperada

- diagnóstico, direção recomendada, execução e validação

## Observações

- Use o nome exato da skill ao invocar.
- Anexe logs, arquivos, prints, layout, consultas ou trechos de código quando houver.
- Declare o formato desejado da resposta: plano, parecer, checklist, arquitetura, auditoria, rollout ou correção.
