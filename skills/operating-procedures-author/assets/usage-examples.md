# Operating Procedures Author - guia de uso

## Objetivo

Use when authoring operating procedures, role-based step sequences, control points, exception handling, and audit-friendly operational docs.

## Quando acionar

- the team needs a durable handbook, report, checklist, or dossier
- documentation exists but is inconsistent or hard to use
- operators need better guided material for reviews or launches
- the output must support signoff, audit, or reference use cases

## Quando evitar

- the task needs code or architecture changes rather than documents
- the document would only restate obvious points without adding structure or actionability

## Entradas úteis

- audience, document purpose, and review or signoff expectations
- source material, evidence, and required structure
- known gaps in current documentation or reporting

## Exemplos de invocação

- `/operating-procedures-author audite este caso e proponha uma versão profissional, com riscos, tradeoffs e plano de rollout.`
- `/operating-procedures-author revise esta implementação e devolva uma versão mais profissional, segura e operacional`
- `/operating-procedures-author monte um checklist de validação, rollout, riscos e critérios de aceite`

## Saída esperada

- diagnóstico, direção recomendada, execução e validação

## Observações

- Use o nome exato da skill ao invocar.
- Anexe logs, arquivos, prints, layout, consultas ou trechos de código quando houver.
- Declare o formato desejado da resposta: plano, parecer, checklist, arquitetura, auditoria, rollout ou correção.
