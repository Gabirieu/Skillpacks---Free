# Operating Procedures Author - Implementation Notes

## Practical review angles
- Define the change sequence before implementation begins.
- Identify the exact evidence needed to call the work done.
- Check how this affects support, incident handling, audits, and future changes.
- Keep the target state simple enough that new owners can operate it.

## Rollout guidance
- Start with a constrained slice or shadow validation path when possible.
- Measure before and after with criteria the team agrees on.
- Capture rollback triggers explicitly instead of assuming judgement in the moment.
- Update documentation, templates, and operational expectations alongside the change.

## Suggested output shape
1. current-state summary
2. risk map and tradeoffs
3. target design or workflow
4. rollout and validation plan
5. owner assignments and next actions
