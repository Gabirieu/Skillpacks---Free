# Changelog Release Notes Architect Patterns

## Core principles

- Anchor recommendations in the real system, workflow, and failure modes.
- Make **release-note audience fit** explicit instead of relying on hidden assumptions.
- Connect **breaking-change visibility** to ownership, rollout, and long-term maintenance.

## Common failure modes

- Teams making local changes without considering **repeatable change communication workflow**.
- Important behavior living in tribal knowledge or scattered configs.
- Weak validation, observability, or rollback planning.

## Good outputs

- A grounded diagnosis, a realistic plan, and clear next actions.
- Deliverables that product, engineering, and operations can actually use.
