# Planning Compression Playbook

Use this reference when the real value is turning a messy request into the smallest trustworthy plan that unblocks execution.

## Key decisions

- Anchor the plan on the desired outcome, the key risk, and the evidence needed to call the work done.
- Decide which unknowns are true blockers and which can be handled with a reasonable assumption.
- Choose the smallest step breakdown that preserves clarity without creating chore-level noise.

## Execution rules

- Order steps by dependency and risk so the plan reduces uncertainty early.
- Include validation, rollback, or follow-up checkpoints when a step can create hidden regressions.
- Name tradeoffs and external approvals explicitly instead of burying them in implementation steps.

## Quality bar

- Another operator should be able to execute the plan without rediscovering the same context from scratch.
- The plan should feel action-ready, not like a vague restatement of the request.
