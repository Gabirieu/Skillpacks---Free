# Prompt Ops Governance Architect - guia de uso

## Objetivo

Use when governing prompt changes, review workflows, version control, risk classification, and deployment discipline for prompt-driven systems.

## Quando acionar

- retrieval, RAG, evaluation, or dataset quality is inconsistent
- prompt or model changes need governance and testing
- knowledge ingestion or labeling quality is affecting results
- the team needs a rigorous measurement framework instead of guesswork

## Quando evitar

- the task is generic web content with no AI or data system behind it
- there is no dataset, retrieval layer, or evaluation question to solve

## Entradas úteis

- data sources, feedback signals, and target quality metrics
- current pipeline steps, prompts, retrieval logic, and failure cases
- freshness, governance, and rollout expectations

## Exemplos de invocação

- `/prompt-ops-governance-architect audite este caso e proponha uma versão profissional, com riscos, tradeoffs e plano de rollout.`
- `/prompt-ops-governance-architect revise esta implementação e devolva uma versão mais profissional, segura e operacional`
- `/prompt-ops-governance-architect monte um checklist de validação, rollout, riscos e critérios de aceite`

## Saída esperada

- diagnóstico, direção recomendada, execução e validação

## Observações

- Use o nome exato da skill ao invocar.
- Anexe logs, arquivos, prints, layout, consultas ou trechos de código quando houver.
- Declare o formato desejado da resposta: plano, parecer, checklist, arquitetura, auditoria, rollout ou correção.
